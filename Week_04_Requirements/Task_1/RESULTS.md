# Results of the supplied-corpus run

The submitted requirements were generated by the actual OpenAI-backed LangGraph network. The final requirement prose was not manually substituted. Test doubles are confined to the offline tests.

## Reproduction

```powershell
python run.py run --input data\corpus --output artifacts\corpus_run --max-revisions 5 --max-calls 220 --review-workers 4 --rescan-sources --feedback review_feedback.json --source-audit-rounds 2
python verify.py --input data\corpus --output artifacts\corpus_run
```

Validated with Python 3.12.14 on Windows x64. Exact installed versions are in `requirements-lock.txt`.

It contains 225 successful requests cumulatively. All caches originate from actual API responses; caches are excluded from the submission ZIP.

## Source-grounded external review

Coding-agent source review supplied three additional candidate statements through `review_feedback.json`: notice-delivery reports, explicit consortium throughput and mandatory Section 508 compliance. Python checked their literal evidence against the current corpus and applied them once through the ordinary feedback loop. Their final paragraphs were generated by the model and independently audited; no requirement output was manually substituted. `external-review-feedback.json` records the applied inputs. The option is not needed for other corpora.

## Correction of the previously observed semantic defect

The earlier sample associated a quotation describing Local Admin permissions with a Material Volume Report. The candidate statement itself had also been incorrectly inferred from that quotation. Literal quote lookup and ID coverage could not detect either error. A separate exhaustive semantic auditor was added to check both source-to-candidate interpretation and candidate-to-requirement disposition. Its failures participate in the LangGraph feedback loop. The final run uses this node for every accepted and rejected candidate.

`artifacts/semantic_regression/result.json` records a real API regression: the original unsupported interpretation is rejected, a corrected permissions candidate linked to the wrong report is rejected, and the correct permissions association is accepted. Offline tests separately establish that such a finding triggers another editor pass and that the auditor cannot silently omit candidate IDs.

## Independent artifact verification

`verify.py` reloaded the original corpus and checked original-byte hashes, normalized copies, all source quotations and line ranges, unique IDs, exactly one disposition per candidate, paragraph/priority/rejection structure, exhaustive final semantic assessments, and evidence of the actual model-backed roles. The result is saved in `verification.json`.

## Open questions and limits

The generated document records 5 open stakeholder questions. These preserve source ambiguity rather than inventing decisions. The historical corpus is not modernized. Requirements remain model judgments: no reference gold-standard specification was supplied, so perfect semantic recall, deduplication and correctness are not mathematically established. The assignment explicitly allows imperfect model output when every OS criterion is addressed; `REPORT.md` maps all ANS and OS criteria.

### Retained warnings

The remaining warnings concern source decisions also recorded as open stakeholder questions. They are disclosed rather than replaced with invented algorithms, metrics or policy defaults.

- description: Shelf-space calculation method is ambiguous; the spec permits estimation but lacks an agreed algorithm (matches CAND-00015).
- terminology: Capacity metrics definition is ambiguous (which physical or system capacity metrics to display). It is referenced by CAND-00067 and CAND-00008 lacking a single definition.
- terminology: Default archival retention policy values are not specified (CAND-00131 and CAND-00215 are open questions about policy defaults).
